# 哪些结论可信，哪些只是字段名提示

> [!danger] 最重要的原则
> **反射解码成功 ≠ 确认游戏逻辑。** 静态资源能证明“游戏配置里写了什么”，但无法独立证明“运行时一定怎样处理它”。例如 `rareRaw`、`oyabunProbability`、`talentVNum` 这类名字很有启发性，却不能跳过最终调用链就给出闪光概率或个体机制结论。

## 01. 建议使用五档证据等级

| 级别 | 证明了什么 | Z-A 本批实例 | 仍不能说明 |
| --- | --- | --- | --- |
| E1 — 结构 | 确实能读取 root/vector/vtable 及字段槽位 | 无 schema 的图鉴 EXL 364 行、道具 535 行 | 这些记录的业务字段名 |
| E2 — 字段 | 通过配套 BFBS 真实解析出字段和值 | `encounter.devNo/minLevel/maxLevel` | 加载器是否以及如何使用它 |
| E3 — 关联 | 多个真实数据源的键严格相等并成功匹配 | `encountDataId = encounter.id`，3,268 次引用 0 失配 | 游戏何时执行这条遭遇 |
| E4 — 运行时 | 使用正确 Build ID + 断点/日志，证实配置被读取和赋值 | 目前相关锁闪/RNG 未闭合 | 不同剧情、地图分支可能有例外 |
| E5 — 复测 | 多次/多类别/不同版本实测吻合，并能解释反例 | 尚待对应机制的回归实验 | 不能自动推断未来更新仍相同 |

“静态有这个字段”可以记 E2；“生成器恰好引用这个 encounterId”是 E3；“某个 phase 条件一定是章节限制”必须 E4/E5 支撑。

## 02. 空白、零、-1、255：四种完全不同的情况

FlatBuffers 不是简单的固定长度结构体。在 Table 中，部分字段如果没有写入或与 Schema 默认值相同，序列化时可能根本没有 field slot。当前反射导出器为避免造数据，会保留**未出现字段**而不是强行插入默认值。

| Excel 里看到 | 可能意味着 | 不能直接说 |
| --- | --- | --- |
| 空单元格 | 当前二进制未出现该 field；或转换脚本没有对应键 | 该值必为“无效” |
| `0` | 字段明确输出 0，或者某阶段已填充默认 | 某条件一定是假 |
| `-1` | 游戏常用占位/自动分配候选值，也可能是合法 enum | 个体真的为 -1，或必然随机 |
| `255` | 8 位边界值、枚举 sentinel 候选 | 特性编号 255 的定义已证实 |
| `{}` | 子对象存在，但所有字段可能被省略 | 训练家没有招式、没有努力值 |
| `[]` | 对应向量存在但长度为 0 | 游戏一定不会动态生成 |

尤其 `ZA_spawn_points.csv` 中，`matchedTransform=1` 说明找到源 Transform 的 `Name`；但即使这时 `x` 空白，也可能是源 `Position.X` 默认零未显式存储，需要回源 JSON/Schema 才能确定真正的值。

## 03. `rareRaw` 和 `rareTypeRaw` 不能混为闪光机制

实际遭遇表的 1,966 行中，`rareRaw` 有三种整数：
- `1073741823`：1,684 行；
- `536870911`：281 行；
- `805306367`：1 行。

这些数值可能是标志或特殊范围边界，也可能反映不同对象类型；**目前没有足够代码证据确定它们是锁闪、闪率或 PID 筛选参数**。同时，训练家队伍中的 `rareTypeRaw` 源字段是 `poke*.rareType`，并不是与遭遇 `rare` 同一字段：实际 8,005 个成员中 **8,000 条值 1、5 条值 2**。这不等于 5 只闪光宝可梦——枚举含义与最终结果尚待证明。

> [!warning] 不能用极端数值猜业务定义
> `536870911`、`1073741823` 虽然看起来不像常规百分比，但猜它们是“PID 上限/掩码/锁闪”依然只是待验证假设。请通过反编译引用、寄存器取值、写回位置和正反样本分别确认。

## 04. 概率相关的三个层次

下面几个字段不在同一层级：
- `encountDataInfoList[].weight`：生成器从候选 Encounter 里挑选时可能使用的**权重原值**；
- `encounter.oyabunProbability`：遭遇对象上的**头目相关原值**；
- `itemDropInfoList[].dropProbability` 与 `pokemon_drop.itemLotteryDataList[].weight`：掉落的不同阶段。

它们的总和可能有归一化/条件过滤/抽样次数等运行时规则。一个候选项 `weight=100` 并不保证在所有天气、章节、刷新条件下“100% 出现”；`oyabunProbability=5.0` 也不能未经代码验证直接宣布实际 5% 头目率。

## 05. 名称推导和真实外键不一样

- **真实匹配：** spawner `encountDataInfoList[].encountDataId` 与 encounter `id` 文本相等；
- **真实匹配：** spawner `appearanceSpawnerObjectInfoList[].objectName` 与 transform `Name` 文本相等（部分命中）；
- **源字段存在：** 348 个 spawner 对象可见 `zoneInfo.zoneId`，可以逐条以此为线索找 zone；
- **启发式：** 汇总 `zoneIdInferredFromSpawnerName` 由 spawner ID 用正则截取，不是原始 zoneInfo 字段。

**为什么文档不直接给整张游戏图？** 因为当前仍有 924 个生成点位置引用未按名称匹配，也有许多生成器未带可推断的 zone 文本；把这些对象强行放到地图上，会引入错误。

## 06. 统计上的“成功”也有几种含义

| 已验证 | 成立的结论 | 不成立的结论 |
| --- | --- | --- |
| 13,181 个 Trinity Pack 的原生提取检查点 | 原生 Pack/Hash 提取审计完成 | 全部文件的二次语义解析完成 |
| 本轮 20/20 BFBS 表 | 这 20 个配对二进制可以按 Schema 解码 | 所有图鉴、技能、脚本和纹理均已还原 |
| 3,268 次遭遇引用全部匹配 | 这批 spawner 的 encounter ID 都能关联 | 581 条无引用遭遇一定是废弃配置 |
| 1,302 / 2,226 名称匹配 | 有对应 Transform Name 的记录数量 | 其余 924 个目标完全没有坐标 |
| EXL 根数组记录数 364/396/535/6 | 基础结构边界、记录数可恢复 | 已确定物种/道具/商店总量 |

全盘二次转换的旧审计仍报告 `nativePathCoverageComplete=false` 与 `semanticConversionComplete=false`，见 [[01-资源树与证据等级]]。

## 07. 静态地址、文件偏移和内存地址怎么区分

- `tableOffset=6396`：**图鉴 .bin 文件内**字节位置；仅用于回到源文件查看结构。
- `Position.X=-406.921`：**三维场景坐标**，与指针没有关系。
- `sourcePath`：Git 仓库中的源文件相对路径，不是内存映射。
- `main+0x123456`：主程序模块相对偏移（RVA），**本轮 CSV 没有导出这样的运行时地址**。
- `Build ID`：用于确认内存断点是否对应这一个可执行版本，不能跨游戏更新直接复用 RVA。

更多 [[07-ExeFS地址与动态验证]]、[[21-锁闪与个体字段研究清单]]。

## 08. 一张数据卡应该记下什么

建议每个具体结论同时记录：
- `gameVersion=2.0.2`、原始文件相对路径和 SHA-256；
- `sourceTable`、`recordId`、字段路径（如 `talentValue.hp`）；
- 解码值、缺省状态、Schema 证据；
- 关联键和 JOIN 命中结果；
- 若声明动态行为，记录 Build ID、`main+RVA`、采样场景和反例；
- `confidence = E1/E2/E3/E4/E5` 和“未解决疑问”。

无法确认时写 **unknown / 未验证**，不要悄悄写 false、0 或“默认随机”。
