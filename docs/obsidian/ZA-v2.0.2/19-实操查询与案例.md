# 真正使用这批 CSV：四种查询方法

## 01. 第一个问题：物种 460 有哪些遭遇配置？

从 [ZA_encounters_flat.csv](https://github.com/969981/ZA_Resources/blob/docs/za-v2.0.2-obsidian-extraction/Unpack/v2.0.2/romfs/arc/data.trpfs/virtual_converted/_tables/encounters/ZA_encounters_flat.csv) 筛选：

- `speciesId = 460`；
- 按 `encounterId` 分组，观察 `minLevel/maxLevel` 与 `oyabunProbability`；
- 如果需要地图/坐标，继续用第二张 `ZA_spawner_encounter_join.csv` 按 `encounterId` 查；
- 注意同一物种可能有多个任务、野生、头目、事件配置，不能简单选第一行。

## 02. 第二个问题：某个野生区有哪些宝可梦？

在 `ZA_spawner_encounter_join.csv` 筛选 `zoneIdInferredFromSpawnerName = a0201_w01`。在本批**实际导出**中，这个筛选对应：

- **18 条**生成器→遭遇引用；
- **18 个**不同生成器 ID；
- **10 个**不同遭遇 ID／物种编号；
- 这 18 个生成器的出生物体都在 `ZA_spawn_points.csv` 找到了坐标名称匹配。

部分实测明细：

| spawner 后缀 | encounter 物种编号 | 源 min–max | 原始头目字段 |
| --- | ---: | --- | ---: |
| `001_A` | 460 | 33–35 | 100.0 |
| `011`、`012` | 361 | 32–34 | 5.0 |
| `021`、`022` | 459 | 32–33 | 5.0 |
| `031`、`032` | 582 | 35–36 | 5.0 |
| `041`、`042` | 673 | 32–34 | 5.0 |
| `051`、`052` | 712 | 32–33 | 5.0 |
| `061_A` | 713 | 34–36 | 100.0 |

> [!important] 这个列表的边界
> 筛选条件用的是 **spawnerId 字符串正则推断**，不是游戏中一定完整的区域遭遇清单；即使这些样本在原始生成器中也能看到 `zoneInfo.zoneId=a0201_w01`，其他生成器可能有不同的 ID 方案或通过事件调用。特别是 outzone 的记录，不能用同一个筛选条件认定完全覆盖。

## 03. 第三个问题：生成器坐标在哪？

在 `ZA_spawn_points.csv` 搜索 `spawnerId=id_spn_a0201_w01_v01_001_A`：

| 字段 | 值 |
| --- | --- |
| `objectName` | `spn_a0201_w01_v01_001` |
| `matchedTransform` | `1` |
| `x` | 约 `-406.921` |
| `y` | 约 `-1.261` |
| `z` | 约 `-831.644` |

这是从 `Position` 读取的世界/场景资源坐标，不是内存偏移，也不能直接充当安全传送坐标。更多细节见 [[14-生成器刷新与坐标]]。

## 04. Excel 筛选一步一步来

1. 下载 `_tables/encounters/ZA_spawner_encounter_join.csv` 的原始完整文件，或在 GitHub 网页看前 100 行预览。
2. Excel → 数据 → 从文本/CSV → 选 UTF-8。**字符串 ID 按文本导入**。
3. 对 `zoneIdInferredFromSpawnerName` 筛选 `a0201_w01`。
4. 同时选 `speciesId/minLevel/maxLevel/oyabunProbabilityRaw` 比较各候选记录。
5. 再以 `spawnerId` 为键，到 `maps/ZA_spawn_points.csv` 查 `matchedTransform/x/y/z`。
6. 如果想看 `spawnPositionsJson` 里的多个对象，不能直接把 JSON 单元格当成 CSV 表头；使用下面的 Python 示例。

## 05. PowerShell 快速查找

在仓库根目录运行：

```powershell
$base = "Unpack/v2.0.2/romfs/arc/data.trpfs/virtual_converted/_tables"
$enc = Import-Csv "$base/encounters/ZA_spawner_encounter_join.csv"
$enc |
  Where-Object { $_.zoneIdInferredFromSpawnerName -eq "a0201_w01" } |
  Select-Object spawnerId, encounterId, speciesId, minLevel, maxLevel, oyabunProbabilityRaw |
  Format-Table -AutoSize

$pts = Import-Csv "$base/maps/ZA_spawn_points.csv"
$pts |
  Where-Object { $_.spawnerId -eq "id_spn_a0201_w01_v01_001_A" } |
  Select-Object objectName, matchedTransform, x, y, z
```

PowerShell 的 `Import-Csv` 是按表加载的，`*.records.csv` 某些行包含巨大的嵌套 JSON，不建议直接在 Excel 打开这些行；优先使用归一化的 `ZA_*.csv`。

## 06. Python 标准库，按宝可梦、区域、训练家交叉查询

保存以下代码为仓库根目录的 `query_za.py`：

```python
from pathlib import Path
import csv
import json

root = Path("Unpack/v2.0.2/romfs/arc/data.trpfs/virtual_converted/_tables")
csv.field_size_limit(64 * 1024 * 1024)

def read(group, filename):
    with (root / group / filename).open(encoding="utf-8-sig", newline="") as f:
        return list(csv.DictReader(f))

join = read("encounters", "ZA_spawner_encounter_join.csv")
points = read("maps", "ZA_spawn_points.csv")
parties = read("trainers", "ZA_trainer_parties.csv")

# 查询一个区域（注意这列是从 spawner ID 推导的区域）
rows = [r for r in join
        if r["zoneIdInferredFromSpawnerName"] == "a0201_w01"]
for row in rows[:20]:
    print(row["spawnerId"], row["speciesId"],
          row["minLevel"], row["maxLevel"])

# 某一物种在所有生成器中的引用
for row in join:
    if row["speciesId"] == "460":
        print("460 reference:", row["spawnerId"], row["encounterId"])

# 找某一个生成器对应的位置
for pt in points:
    if pt["spawnerId"] == "id_spn_a0201_w01_v01_001_A":
        print("XYZ:", pt["x"], pt["y"], pt["z"])

# 训练家一条完整队伍
members = [p for p in parties if p["trainerId"] == "Ev_m08_7000"]
for m in sorted(members, key=lambda x: int(x["slot"])):
    print("slot", m["slot"], "species", m["speciesId"], "lv", m["level"])
    # 这里原始招式节点可能是 {}，不能自行解释成 0 号招式
    moves = json.loads(m["movesJson"])
    print("moves", moves)
```

运行 `python query_za.py`。CSV 中数值默认是**字符串**，因此比较 `"460"`、`"a0201_w01"`。排序等级时应转为 `int`，避免字典序错误，例如 "100" 排在 "20" 前面。

## 07. 如果想对海量表做 SQL JOIN

可先使用 Python 标准库 `sqlite3` 将 CSV 导入临时 SQLite，或使用 Excel Power Query。真实连接键是：

```sql
SELECT e.spawnerId, e.encounterId, e.speciesId,
       e.minLevel, e.maxLevel, p.objectName, p.x, p.y, p.z
FROM spawner_encounter AS e
LEFT JOIN spawn_points AS p ON p.spawnerId = e.spawnerId
WHERE e.speciesId = '460';
```

上述 SQL 表名 `spawner_encounter` / `spawn_points` 是你**自行将 CSV 导入数据库后创建的表名**，仓库里并没有预置这两个 SQLite 表。必须使用 `LEFT JOIN` 保留没有坐标的生成器，不要使用 `INNER JOIN` 把未匹配记录静默删除。

**重要：** 一个生成器可能对应多条遭遇，又可能对应多个位置；这个 JOIN 是 **多对多潜在展开**，行数未必等于不同物种/不同生成器数。应对主键/外键的基数做对账。

## 08. Obsidian 的查询思路

Obsidian 笔记可用 `[[13-遭遇表逐列解读]]`、`[[14-生成器刷新与坐标]]` 等内部链接；CSV 本身并不会自动被 Obsidian Dataview 解析为数据库。若确实需要 Dataview，可以按物种/区域生成 `.md` 卡片，带 YAML：

```yaml
---
speciesId: 460
encounterId: ect_a0201_w01_v01_z460_Alpha
zoneId: a0201_w01
levelMin: 33
levelMax: 35
evidence: id-join-and-raw-zoneinfo
sourceVersion: "2.0.2"
---
```

**这是卡片格式示例，未在仓库中批量生成这些卡片。** 不要将 `evidence` 字段的示例直接用于未验证的区域关联；具体记录应按证据写入。
