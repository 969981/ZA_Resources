# 地图与条件：在哪、什么时候出现

## 01. 别混淆六种标识

| 类型 | 实际字段/例子 | 它是什么 |
| --- | --- | --- |
| `zoneID` | `a0101_w01`、`a0201_w01` | 野生区域代码 |
| `areaName` | `farea_wild_a0101_w01` | 场景区域对象名 |
| `placeNameKey` | `PLACENAME_wild_a0101_w01` | **多语言文本键**，不是中文地点 |
| `fastTravelFlagId` | `flag_FastTravel_wild_a01_01` | 快速旅行相关旗标名 |
| `areaSceneName` | `t1` | 场景分组字符串 |
| `objectName` | `spn_a0201_w01_v01_001` | 具体生成物体名，通常要去 Transform 表找坐标 |

与此不同，`scenePath`、`createScenePath` 往往指资源或场景容器路径；`X/Y/Z` 是位置坐标；`main+RVA` 才是模块内程序偏移。不要混用。

## 03. ZA_zones.csv 六列

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `zoneID` | `field_wild_zone.zoneID` | 野生区代码，可用于原始对象直接关联（若确有此字段） |
| `areaName` | `areaInfo.areaName` | 资源内场景名 |
| `placeNameKey` | `areaInfo.subAreaName` | 本地化文字 ID，必须用消息资源转译 |
| `fastTravelFlagId` | `areaInfo.fastTravelFlagId` | 解锁传送候选条件的字符串 ID |
| `layer` | `layer` | 区域层级的原始数值，如 7 |
| `bgm` | `areaInfo.bgm` | BGM 字符串 ID，如 `VS_WILDZONE` |

样本：`a0101_w01` 对应 `farea_wild_a0101_w01`、`PLACENAME_wild_a0101_w01`、`flag_FastTravel_wild_a01_01`。这些字段已经在真实文件中读出，**与中文地区名和实际传送权限的业务关联仍须验证**。

## 04. “条件 JSON”长什么样

`wild_zone` 源对象可以包含：

```json
{
  "zoneId": "a0601_w01",
  "areaSceneName": "t1",
  "weight": 50,
  "activationCondition": [
    {"element": [
      {"param": [
        {"condition": "flag_condition", "op": 1,
         "param": ["flag_Ev_m09_3200"]},
        {"condition": "phase_condition", "op": 1,
         "param": ["0"]}
      ]}
    ]}
  ]
}
```

**怎么读：** 这里能确定“存在按 `flag_condition`、`phase_condition` 分类的条件项，且它们有 op 代码和参数字符串”。但尚不清楚：
- `op=1`/`2`/`5` 分别如何比较；
- 最外层 `activationCondition[]` 之间是 OR 还是 AND；
- `element[]` 与 `param[]` 嵌套层的实际组合规则；
- `phase=0` 与剧情章回是否直接对应；
- `weight=50` 参与哪个阶段的抽选。

因此不能把上述 JSON 简化为“通关第九章解锁”“故事阶段大于某阈值”等没有代码证据的描述。

## 05. Spawner 的条件不仅一层

真实生成器 `id_spn_d03_01_ev_001` 有：

```json
{
  "activationCondition": [
    {"element": [
      {"param": [{"condition":"phase_condition","op":1,"param":["62920"]}]},
      {"param": [{"condition":"flag_condition","op":2,
                  "param":["flag_M6_PokeSpawner01"]}]}
    ]}
  ],
  "encountDataInfoList": [
    {"encountDataId":"ect_d03_01_z094_ev",
     "weight":100, "maxCount":1,
     "activationCondition":[
       {"element":[{"param":[{"condition":"force_condition"}]}]},
       {"element":[{"param":[{"condition":"force_condition"}]}]}
     ]}
  ]
}
```

此例表示至少有两层独立记录的条件：**Spawner 顶层**和**遇敌候选项**。如果 CSV 只展平 `encountDataInfoList[].activationCondition`，就会漏掉 `spawner.activationCondition`。研究剧情刷新必须检查原始 `spawner.json.gz` 或 `spawner.records.csv`。

## 06. 坐标、旋转、父对象

坐标 `Position.X/Y/Z` 来自 `pokemon_spawner_transform_array`，按物体 `Name` 关联。坐标中可出现负数、小数、零缺省，不能直接认为是地理经纬度。`Rotation.Y` 等数字也不应未经资源验证直接宣称角度单位或坐标系 handedness。

若要生成传送功能/游戏内实时定位，还需要：
1. 从 `field_area_jump_point` 找入口名和坐标；
2. 从区域 `areaName/scenePath` 识别其所属场景；
3. 查明场景原点、父节点变换和游戏内加载状态；
4. 在运行时用正确 Build ID 验证 `main+RVA` 调用链；
5. 验证切场景、流式加载和地图安全点，而不是拿 CSV 坐标直接写内存。

## 07. 静态数据不能回答的问题

- 这里是早上还是夜间生成？需检查更多条件表和程序天气/时段系统；
- 某只宝可梦多久刷新？`coolTimeInfo.time` 不等于已经验证的秒数；
- `outzone` 和 `wild_zone` 的真实边界是什么？资源命名只是线索；
- 地图中文显示是什么？需要 `ik_message` 多语言解析；
- 为什么某 `spawner` 匹配不到 transform？可能是动态生成、父节点、另一套资源或无坐标显示。

这些问题应为每条假设记录来源、实际值和反例，见 [[20-字段缺省值与证据级别]]。
