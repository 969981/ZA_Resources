# 批量导出、CSV/JSON/SQLite 和验收

## 推荐流程

1. 固定 `v2.0.2`、当前 Git commit、`main` Build ID、原始文件路径与 SHA256。
2. 从 `Unpack/v2.0.2/romfs/arc/data.trpfs/_index/file_index.tsv.gz` 和 `pack_index.tsv` 建原始清单；包含归档/分卷原始文件与 Hash 信息。
3. 全量扫描 `*.bfbs + *.bin` 成对文件，按 [[02-从TRPFS到JSON]] 独立解码至同目录结构下的 `.json`；保留成功与失败记录。
4. 仅对已有确证的主键和外键关系进行规范化/联表；每个 JOIN 输出未命中和重复键，不能静默丢数据。
5. 对 `world/exl` 无 schema 文件独立调查并列出 `UNSUPPORTED`，不能按后缀重命名假装解码。
6. 多语言 DAT/TBL 不按数组下标硬联；用经验证的 key 和实际游戏语义核实。
7. 依次生成 CSV、JSON、SQLite。对 Excel 用户，64 位 Hash、ID（可能带前导零）、十六进制地址均以**文本**写出。

## 验收标准

- 原生：`full-extract-progress.json` 的 `state=COMPLETE`，`full-extract-audit.json` 的 `complete=true,failed=0,unseen=0`。
- 二次：重新生成并检查 `virtual_converted/_index/native-coverage-audit.json` 的 `nativePathCoverageComplete` / `semanticConversionComplete`，二者当前为 **false**；尚缺 39,779 原生路径；`UNSUPPORTED=39,720`、`FAILED=129`。
- 每个 JSON 有合法 schema/解析器版本；每个输出有源路径、哈希与状态。
- 对多形态 species、DLC、剧情固定、头目、地点映射进行抽样回读。
- 不将仅通过 FlatBuffer vtable bounds 的结果当成完成语义解码。
- 对锁闪和 IV/RNG 用运行时证据验证，UNKNOWN 显式保留。

## 优先级

**P0：** 先真正确认遭遇、刷新器、地点三组 JSON 的字段和外键；多语言物种/招式/道具名称解出。

**P1：** 图鉴/道具/商店主表 `exl` 解码、学习表定位、区域与传送点联表。

**P2：** `main.elf` 锁闪、IV/性格及 RNG 生成链做断点验证，形成 Build ID 绑定的地址索引。

每个结果建一页 [[09-研究证据卡模板]]，留完整的失败清单和反例，不只展示成功数据。
