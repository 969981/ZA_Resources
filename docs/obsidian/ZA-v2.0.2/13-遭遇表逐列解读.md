# 遭遇表怎么理解：22 列逐项解释

**文件：** [ZA_encounters_flat.csv](https://github.com/969981/ZA_Resources/blob/docs/za-v2.0.2-obsidian-extraction/Unpack/v2.0.2/romfs/arc/data.trpfs/virtual_converted/_tables/encounters/ZA_encounters_flat.csv)。[前 100 行](https://github.com/969981/ZA_Resources/blob/docs/za-v2.0.2-obsidian-extraction/Unpack/v2.0.2/romfs/arc/data.trpfs/virtual_converted/_tables/encounters/ZA_encounters_flat.preview.csv)。

数据来自 `world/ik_data/field/pokemon/encount_data/encount_data/encount_data_array.bin`，配套 `.bfbs`；经 `scripts/Export-ZA-Databases.py` 解码，再由 `Join-ZA-EncounterData.py` 展开。**1,966 行，每行是一种“遭遇配置”而不是地图上的一只宝可梦。**

## 01. 列字典

| CSV 列名 | 源字段 | 含义/读法 | 确认程度 |
| --- | --- | --- | --- |
| `encounterId` | `id` | 遭遇定义的**唯一字符串键**，用于生成器引用 | 实际外键匹配 |
| `speciesId` | `devNo` | 宝可梦种类编号，例如 460、361、359 | 字段与编号已读出 |
| `formNo` | `formNo` | 形态编号；空值要看默认值 | 字段存在；枚举未完全映射 |
| `minLevel` | `minLevel` | 遭遇配置的最低等级 | 原始数字，最终等级可受代码/条件影响 |
| `maxLevel` | `maxLevel` | 遭遇配置的最高等级 | 同上 |
| `rareRaw` | `rare` | 游戏内部 `rare` 字段的原始整数 | **不等于已验证闪率/锁闪** |
| `sexRaw` | `sex` | 性别相关的原始枚举或占位数 | `-1` 等需核实 |
| `natureRaw` | `seikaku` | 性格相关原始枚举 | 数字→性格对应待校验 |
| `abilityRaw` | `tokusei` | 特性相关原始字段 | `255` 并非真实特性 ID 结论 |
| `talentScale` | `talentScale` | 与个体/尺度相关的原始参数 | 实际单位及默认值未知 |
| `talentVNum` | `talentVNum` | 与个体数值个数相关的参数 | 需要验证生成逻辑 |
| `oyabunProbability` | 同名字段 | 头目相关的数值；如 5.0、100.0 | **原始字段名，不代表最终概率** |
| `oyabunAdditionalLevel` | 同名字段 | 头目附加等级相关值；如 9、10 | 加算逻辑需要追踪 |
| `ivHp` | `talentValue.hp` | HP 个体相关原始设置 | 出现 `-1`，通常是未指定候选 |
| `ivAtk` | `talentValue.atk` | 攻击设置 | 同上 |
| `ivDef` | `talentValue.def` | 防御设置 | 同上 |
| `ivSpAtk` | `talentValue.spAtk` | 特攻设置 | 同上 |
| `ivSpDef` | `talentValue.spDef` | 特防设置 | 同上 |
| `ivAgi` | `talentValue.agi` | 速度相关设置 | 同上 |
| `wazaListJson` | `wazaList` | 预置招式集合，例如 `waza1=399` | 招式 ID 尚未在此表翻译为中文 |
| `itemDropInfoJson` | `itemDropInfoList` | 抽选道具表 ID、次数及条件 | 可进一步关联掉落表 |
| `activationConditionsJson` | `activationCondition` | 出现/启用条件嵌套结构 | `condition/op/param` 仍待事件运行时核验 |

> [!tip] Excel 的空单元格不一定等于“没有配置”
> 原始 FlatBuffers 使用 vtable 标记字段是否在序列化时出现；某些值等于默认值时，二进制可能省略它。当前导出器会**保留省略状态**，不会随意补 0。所以空白、`0`、`-1`、`255` 应分开处理。

## 02. 真实数据示例：一只固定事件配置

`encounterId = ect_boss_0359_01` 的实际字段：

```json
{
  "id": "ect_boss_0359_01",
  "devNo": 359,
  "minLevel": 25,
  "maxLevel": 25,
  "rare": 536870911,
  "talentScale": 255,
  "talentValue": {
    "hp": 31, "atk": 31, "def": 31,
    "spAtk": 31, "spDef": 31, "agi": 31
  },
  "wazaList": {"waza1": 399, "waza2": 232, "waza3": 109, "waza4": 43}
}
```

**正确的读法：** 这条配置声明原始物种编号 359、等级字段固定为 25/25、六项个体设置均为 31，并给出四个招式编号。不能仅凭 `boss` 名称断言玩家何时捕获、是否锁闪、是否存在第二阶段特殊形态。

**不能这样读：** “`rare=536870911` 所以锁闪”、“六 V 保证所有实际场景都是六 V”。后两个结论需要追踪调用这个配置的对象和最终生成流程。

## 03. 真实数据示例：野生区与头目参数

`ect_a0201_w01_v01_z460_Alpha` 的数据是：

```json
{
  "id": "ect_a0201_w01_v01_z460_Alpha",
  "devNo": 460,
  "minLevel": 33,
  "maxLevel": 35,
  "oyabunProbability": 100.0,
  "oyabunAdditionalLevel": 10,
  "rare": 1073741823,
  "seikaku": -1,
  "sex": -1,
  "talentValue": {
    "hp": -1, "atk": -1, "def": -1,
    "spAtk": -1, "spDef": -1, "agi": -1
  }
}
```

为什么看上去是 `Alpha`，但不能直接写死“43–45 级”？因为当前只知道表里有等级范围 33–35 和额外等级 10，**并未验证最终等级计算是否简单相加以及所有场景是否都调用该分支**。真正的目标是：静态记录 → 引用它的生成器 → 游戏内实际结果 → 对应代码。

## 04. 高频特殊数字不能瞎翻译

在本批实际 1,966 条记录中：
- `rareRaw` 出现 **536870911**、**805306367**、**1073741823** 三种原始值；
- `abilityRaw=255` 在全部 1,966 条上都有，不能因此认为所有宝可梦共享一个特性；
- `iv*=-1` 是高频值，而部分事件配置含 `31` 等显式设置；
- `talentScale` 有 `-1`、`128`、`255` 等值；
- 一些记录的 `minLevel/maxLevel` 看似是普通野生范围，另一些是固定级数。

数据层面可以比较值的分布、找异常分支、追踪调用，但**不能直接将这些整数映射为 shiny/IV 算法的确定规则**。见 [[20-字段缺省值与证据级别]]。

## 05. 什么时候应该去另一张表

- 想知道 `encounterId` 实际被哪个刷新点使用 → [[14-生成器刷新与坐标]]。
- 想知道 `itemDropInfoJson` 中 `itemTableId` 实际掉什么物品 → [[16-道具掉落与图鉴原始表]]。
- 想知道 `waza1` 是哪一招 → 需 `ik_message` 多语言名称 + 招式原始编号校验，另见 [[15-训练家队伍与战斗]]。
- 想知道 `activationConditionsJson` 的 `phase_condition` 是否表示某章 → [[17-地图区域与触发条件]]。
- 想用筛选式验证某物种全部配置 → [[19-实操查询与案例]]。

## 06. 对账核验

这张表 **1,966** 条 `encounterId` 均唯一。生成器有 **3,268** 次对遭遇 `id` 的引用，引用全部匹配，但只有 **1,385 种**遭遇 ID 被引用，另 **581** 种未在这批生成器数据中出现。这可能是任务、事件、独立入口或保留内容，**不是未提取文件的证据**。关联明细见 [[14-生成器刷新与坐标]]。
