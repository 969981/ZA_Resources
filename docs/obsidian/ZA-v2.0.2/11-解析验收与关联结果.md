## 无 BFBS 主表的结构探针

确认 `world/exl/` 几组缺失本地 schema 的真实二进制满足 FlatBuffers 的基本 vtable/根向量边界：

| 文件 | 根向量记录数 | 已确认的程度 |
| --- | ---: | --- |
| `pokedex_contents_data.bin` | 364 | 结构 E1 |
| `pokedex_sp_distribution_data.bin` | 396 | 结构 E1 |
| `item_data.bin` | 535 | 结构 E1 |
| `shop_item_lineup.bin` | 6 | 结构 E1 |

这**不是已确认图鉴物种数/实际道具数量/商店数量**；由于没有对应的 schema，字段仍按 `field_id + raw bytes` 导出，不能猜含义。首三张图鉴/道具表第 0 个字段的头三行存在候选值 `1/2/3`，是否为实际 ID 仍需进一步验证。

## 使用与边界

`scripts/Export-ZA-Databases.py` 产生 `*.json.gz`（全部二进制字段还原）、`*.preview.json`、`*.records.csv` 和哈希审计。`scripts/Join-ZA-EncounterData.py` 追加：
`ZA_encounters_flat.csv`、`ZA_spawner_encounter_join.csv`、`ZA_spawn_points.csv`、`ZA_zones.csv`、`ZA_trainer_parties.csv`、`ZA_item_lottery.csv`、`ZA_relation_summary.json`。

**没有结论的领域：** 锁闪和 `rare` 枚举、固定 IV 的实际语义、招式升级习得表、多语言消息键的正式 join、`main+RVA`。这些仍需通过数据 schema 与运行时调用链闭合，不在目前的结构解析成果里“补造”。
