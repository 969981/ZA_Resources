# 怎样看 364 篇自动生成的宝可梦档案

入口：[[22-宝可梦数据档案索引]]。

**本档案按 Personal 中 `presentFlag=1` 的物种编号生成 364 篇 Markdown（362 个在遭遇表中出现，801、809 没有本轮遭遇记录）**，文件名形如 `宝可梦档案/No-0460.md`；每页都是一张“静态宝可梦资料卡”，包含真实简体中文名称、原始来源、遭遇列表、等级与六项 IV、完整 Personal 招式学习表（含中文名、属性、分类、威力、命中、PP 和学习/解锁等级）、地图区域中文标签、训练家队伍及图鉴说明源标签。它适合 Obsidian 的全文检索与双向链接，但**不是已经验证的完整 Z-A 官方图鉴**。

## 一、每篇档案最上面的 YAML 元数据

```yaml
---
speciesId: 460
zaVersion: "2.0.2"
dataOrigin: "encounter-devNo"
pokedexMembership: "unknown"
shinyLocked: "unknown"
encounterConfigCount: 3
spawnerReferenceCount: 9
trainerSlotCount: 50
---
```

以上三个计数与当前已生成的 `No-0460.md` 真实卡片一致：3 条遭遇配置、9 次生成器引用、50 个训练家队伍槽。这里的队伍槽计数不是“50 个不同训练家”，而是数据中出现该物种的成员记录次数。字段含义如下：

| YAML key | 用法 |
|---|---|
| `speciesId` | 遭遇参数的 `devNo`，用于关联多张数据表 |
| `zaVersion` | 数据版本，避免 v2.0.2 与其他版本混淆 |
| `dataOrigin` | 表明物种列表来自遭遇 `devNo`，不是正式图鉴 |
| `pokedexMembership` | 当前固定为 `unknown`，直到 EXL 图鉴结构恢复 |
| `shinyLocked` | 当前固定为 `unknown`，直到找到动态证据 |
| `encounterConfigCount` | 该物种的 encounter ID 数量 |
| `spawnerReferenceCount` | 该物种的 spawner→encounter 引用次数 |
| `trainerSlotCount` | 训练家队伍槽中出现该物种的次数 |

不要直接修改生成脚本中的 `unknown` 成 `true` 或 `false`；这属于需要独立验证的事实。

## 二、每页各节怎么读

### `静态摘要`

列出这只宝可梦在当前提取的**所有遭遇配置**中的最大/最小等级包络，显式形态编号、六项全 31 或全 -1 的记录数、配置招式的记录数。这不是“这只宝可梦在哪儿都能以这个等级出现”。

### `每条遭遇定义`

每行原始 `encounterId`，完整列出 form、等级范围、六项个体原始值、预置招式 ID、`rareRaw` 和头目参数。多条相似 ID 说明不同配置，不要去重掉事件记录。

### `对应生成器、区域与位置`

每个 `spawnerId` 匹配到的 `encounterId`，连同区域**推断**、等级、可匹配到的源坐标。坐标不存在或显示“未找到实值”，不能写“该物种没有出现地点”；它可能来自其它事件入口或变换加载方式。

### `训练家队伍中该物种`

同物种在训练家队伍中的槽位与等级、显式招式 ID。训练家配置不等于野外可捕获；空技能字段可能来自 FlatBuffers 缺省。

### `头目额外招式原始记录`

按照 `oyabun_waza.devNo` 找到的附加技能配置。它不保证普通野生/剧情赠送/头目必定学会该招。

## 三、推荐的 Obsidian 使用方法

1. 克隆 `ZA_Resources` 文档分支，或将 `docs/obsidian/ZA-v2.0.2/` 复制到自己的 Obsidian Vault。
2. 打开 [[22-宝可梦数据档案索引]]，按 `devNo` 选择对应宝可梦。
3. 用 `Ctrl+O` 搜索 `No-0460`，直接打开该物种的 Markdown。
4. 查看完整的遭遇 ID，再切换到 [[25-遭遇区域等级与生成条件专题]] 确认区域/等级含义。
5. 若要研究固定 IV/闪光，阅读 [[24-六项个体值与生成规则专题]] 和 [[21-锁闪与个体字段研究清单]]。
6. 如果想查全部技能、中文技能名，阅读 [[26-招式与技能学习数据专题]] 并按证据补齐消息/技能主表。

GitHub 也可直接打开 [宝可梦档案文件夹](https://github.com/969981/ZA_Resources/tree/docs/za-v2.0.2-obsidian-extraction/docs/obsidian/ZA-v2.0.2/宝可梦档案)。

## 四、自动生成工具与可重复运行

脚本：`scripts/Generate-ZA-PokemonObsidian.py`，只依赖 Python 标准库与已经提交的派生 CSV：

```powershell
# 在 ZA_Resources 根目录
python scripts/Export-ZA-CoreDex.py --repo .
python scripts/Audit-ZA-Rare.py --repo .
python scripts/Generate-ZA-PokemonObsidian.py --repo .
```

输入：
- `_tables/encounters/ZA_encounters_flat.csv`；
- `_tables/encounters/ZA_spawner_encounter_join.csv`；
- `_tables/maps/ZA_spawn_points.csv`；
- `_tables/trainers/ZA_trainer_parties.csv`；
- `_tables/battle/oyabun_waza.records.csv`；
- `_tables/_audit/ZA_relation_summary.json`；
- `_tables/names/ZA_species_names_zh.csv` 与 `ZA_move_names_zh.csv`、`ZA_place_names_zh.csv`；
- `_tables/battle/ZA_levelup_learnsets_zh.csv`；
- `_tables/battle/ZA_move_stats_zh.csv`（902 条技能主数据）；
- `_tables/pokedex/ZA_pokedex_comment_A_zh.csv` / `..._B_zh.csv`。

输出：
- `docs/obsidian/ZA-v2.0.2/22-宝可梦数据档案索引.md`；
- `docs/obsidian/ZA-v2.0.2/宝可梦档案/No-XXXX.md`（364 篇）。

在 GitHub Actions 的 `ZA v2.0.2 real BFBS data export` 工作流中，CSV 导出完成后自动运行本脚本并提交到当前文档分支。因此数据更新后可重新生成，不必手改每一张卡。

> [!warning] 如果以后数据变多
> 当前脚本以 v2.0.2 实测 **364 个 Personal 可用 speciesId** 与 **362 个 Encounter speciesId** 为运行验收断言。新版本或新增资源会改变数量，应先核验新来源及 `ZA_relation_summary`，再修改断言；不要默默把更多物种当成已证实的图鉴新增。

## 五、如何为每张卡补充真实中文名字

建议使用单独的 `species_names_verified.csv`，包含：

```csv
speciesId,formNo,language,displayName,messageKey,messageSourceHash,evidence
```

并在明确校验 `monsname.dat/tbl` 索引与 `devNo/formNo` 对应后，由生成器把这些名称并入卡片。不要靠外部全国图鉴序号自动套入，也不要直接修改大量生成卡片后让 Actions 覆盖。

如果你需要人工研究/证据，单独写 `宝可梦研究/No-0460-证据.md` 之类的附加笔记，再由生成页面链接它，避免重新生成时丢失人工结论。
