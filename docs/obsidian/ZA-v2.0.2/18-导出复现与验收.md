# 从 .bin 到 CSV：如何复现这批真实数据

> [!success] 已验证到的范围
> 对当前明确选取的 20 组 `.bfbs+.bin` 文件，GitHub Actions 测试为 **20/20 解析成功、0 失败**；抽取 1,966 条遭遇、2,211 个生成器、3,268 个遭遇引用且全部命中。除此之外，4 张 EXL 主表只做 `STRUCTURE_ONLY` 结构探针，不应与真正的 BFBS 字段解析混为一谈。

## 01. 输入路径

在仓库根目录执行。原生文件统一位于：

```text
Unpack/v2.0.2/romfs/arc/data.trpfs/
├── virtual/                     # 解包出来的只读原始数据
│   └── world/
│       ├── ik_data/field/...     # 遭遇、spawner、坐标、头目...
│       ├── ik_data/trainer/...   # 训练家
│       └── exl/...               # 图鉴、道具、商店主表
└── virtual_converted/
    └── _tables/                 # 已提交到 GitHub 的分类 CSV
        ├── encounters/
        ├── maps/
        ├── trainers/
        ├── items/
        ├── pokedex/
        ├── battle/
        ├── _audit/
        └── README.md
```

`virtual/` 代表真实来源；`virtual_converted/_tables/` 是从来源计算出来的**派生数据**。勿直接编辑原始 `.bin` 来修正 CSV 的显示问题。

## 02. 四个脚本各自负责什么

| 脚本 | 功能 | 输入 | 主要输出 |
| --- | --- | --- | --- |
| `Export-ZA-Databases.py` | 根据 FlatBuffers Reflection 读出字段和数组 | 20 组 `.bfbs+.bin` | 完整 `*.json.gz`、`*.records.csv`、`manifest.json` |
| `Join-ZA-EncounterData.py` | 展开/关联遭遇、spawner、transform、队伍和掉落 | 上一步 JSON | `ZA_encounters_flat.csv` 等 6 张分析 CSV |
| `Probe-ZA-RawEXL.py` | 检查无 Schema 的 EXL 表根向量/vtable | `world/exl/*.bin` | `EXL_*_raw.csv/json`（结构级） |
| `Publish-ZA-CSV.py` | 分类复制、校验、写 GitHub 可浏览的前 100 行 CSV | 前三步导出 | `virtual_converted/_tables/` 下的 31 个完整 CSV + 11 份预览 |

所有脚本位于 [scripts/](https://github.com/969981/ZA_Resources/tree/docs/za-v2.0.2-obsidian-extraction/scripts)。解析器使用 Python 标准库并内置边界检查/对象次数保护；**不需要先安装 flatc**。

## 03. Windows PowerShell 本地执行（仓库根目录）

```powershell
# 需要 Python 3.12 或兼容版本，当前目录为 ZA_Resources
python scripts/Export-ZA-Databases.py --repo . --workers 4 --samples 5 --require-all

# 验证 encounterId 真实外键，同时制作更适合 Excel 查看的一行一条 CSV
python scripts/Join-ZA-EncounterData.py --input .za-work/za-data

# 对暂时找不到 BFBS 的 4 张 EXL 表导出原始槽位
python scripts/Probe-ZA-RawEXL.py --repo . --out .za-work/za-data --require-all

# 整理到对应分类目录 + 预览
python scripts/Publish-ZA-CSV.py --repo . --input .za-work/za-data --preview-rows 100
```

**按需处理：** 若只想重解野生区或遭遇，用：

```powershell
python scripts/Export-ZA-Databases.py --repo . --only encounter spawner wild_zone field_wild_zone
```

但此时只生成局部表，**不能直接运行依赖所有指定表的 Join/Publish 全量验收**；局部结果也不应写回全量发布目录。

**全仓扫描：** `--all-pairs` 可在本地完整 checkout 下扫描所有有配套 `.bfbs+.bin` 的资源；属于扩展探索，不等于“其他未知格式也能成功解码”。当前 Actions 专注于指定的 20 组，并不运行全仓扫描。

## 04. 看 manifest 才知道真的解析到哪一步

`_audit/manifest.csv` 一行是一种源数据表（总共 20 行），主要字段：

| 字段 | 用途 |
| --- | --- |
| `name` | exporter 中的逻辑表名，如 `encounter` |
| `status` | `DECODED_REFLECTION`＝按已反射的字段成功解码 |
| `bytes` | 原始 .bin 文件的字节长度 |
| `rootRecordCount` | **根层记录数量**，可能是容器数量而非业务条数 |
| `schemaRoot` | 真实 BFBS 根对象类名 |
| `binarySha256` | 对应原始 .bin SHA-256；可验证同一版数据 |
| `source` | 相对于 `virtual/` 的原始路径 |
| `error` | 失败时的原因，成功时为空 |

**为什么 encounter 的 `rootRecordCount=13`，但展开后的遭遇是 1,966？** 根对象是 `EncountDataDBArray`，内有 13 个 `values` 组，每个组又有 `root[]` 数组；完整业务记录数是对各组 `root[]` 求和。

查外键关联质量用 `_audit/ZA_relation_summary.json`。其中 `allReferencesResolved=true`、`unresolvedEncounterIds=[]` 表示 3,268 次字符串外键引用都找到了，不代表对应游戏事件都能触发。

## 05. Excel 和 Obsidian 的正确打开方式

- 仓库 CSV 写入 `utf-8-sig`，Excel 一般可以正确识别中文、日文以及字段名。
- 对 `speciesId`、`formNo`、`itemId`、`encounterId`、`spawnerId` 使用**文本字段**，避免自动把 ID 转成日期、科学计数或误删前导零。
- `spawnPositionsJson`、`activationConditionJson` 等列是字符串形式的 JSON 数组，不会自动分成多个 Excel 列；可用 Python 的 `json.loads` 递归展开。
- GitHub 网页太大的表可能无法直接预览；打开同名 `.preview.csv` 只能看到前 100 行；正式完整文件仍是无 `.preview` 的原 CSV。
- **Obsidian 默认并不把 CSV 自动当成可查询数据库。** 在 Obsidian 用 Markdown 笔记阅读原理，批量筛选用 Excel/Python/SQLite；想用 Dataview，请先将选定记录转换为带 YAML 属性的 Markdown 卡片。

[ZA real BFBS data export 工作流](https://github.com/969981/ZA_Resources/actions/workflows/za-real-data-export.yml)

1. 打开对应成功的运行；
2. 看 `Decode v2.0.2 native table pairs`：应显示 `RESULT: 20/20 decoded`；
3. 看 `Build normalized linked CSVs`：核验遭遇 ID 失配为 0；
4. 看 `Probe schema-less EXL`：4 项成功但都只是结构级；
5. 在 Artifacts 下载 `ZA-v2.0.2-FlatBuffers-RealData`，里面有完整的 gzip JSON、CSV、样本和 SHA-256 清单；
6. 已提交、可在线浏览的 CSV 在 [virtual_converted/_tables](https://github.com/969981/ZA_Resources/tree/docs/za-v2.0.2-obsidian-extraction/Unpack/v2.0.2/romfs/arc/data.trpfs/virtual_converted/_tables)。

参考成功运行：[数据提取 #42165788503](https://github.com/969981/ZA_Resources/actions/runs/42165788503)；发布目录通过 GitHub 实际核查存在 31 个完整 CSV、11 个预览 CSV。当前发布工作仍在文档 PR 分支，未合并前 `master` 看不到新增笔记/CSV。

## 07. 五条验收原则

1. 所有导出的数字必须能追踪到源 `.bin` 和匹配 `.bfbs`，清单中有 SHA-256。
2. 遭遇外键必须使用原始键严格相等，不能因为物种编号相同就算匹配。
3. 位置信息命中率不得伪造；`matchedTransform=0` 的记录要保留。
4. 无 Schema 的 EXL 数据必须用 `STRUCTURE_ONLY`，不能改成 `CONVERTED`。
5. 动态机制（锁闪、等级最终加成、刷新概率、实际游戏地址）必须有可复现的 Build ID 和代码/游戏内对照证据。

参见 [[01-资源树与证据等级]]、[[20-字段缺省值与证据级别]]。
